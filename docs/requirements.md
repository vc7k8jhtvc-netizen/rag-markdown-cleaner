# Requirements

本文记录当前项目源码的功能要求、非功能要求、已确认范围和最低验收标准，不作为功能宣传、未来路线图或版本发布说明。具体版本行为和发布状态以根目录 `CHANGELOG.md` 为准。

实际实现状态以当前代码和可重复的测试结果为准。

## 功能要求

### 工作目录与输入

- 支持 `--base-dir`、`RAG_CLEANER_HOME` 或当前目录作为工作目录。
- 工作目录必须包含 `prompt.md`。
- 递归发现 `input/` 内的 Markdown。
- 拒绝 cleaned 输出、路径穿越、不安全路径和符号链接输入。
- 支持 UTF-8 BOM、UTF-8、GB18030 和 GBK 输入。
- 拒绝超过配置上限的文件。
- 支持符合既定 schema 的 JSON 文件选择清单。

### 规划与分片

- 源字节、解码文本和 SHA-256 必须来自一致的文件快照。
- 分片必须满足 `"".join(chunks) == source_text`。
- 应在安全边界保留 fenced/indented code、表格、列表、引用和 YAML Front Matter。
- 无法安全拆分且超过限制的结构必须规划失败，不能静默破坏。

### API 处理

- 正式处理要求配置 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`。
- 接口必须兼容 `/chat/completions` 流式响应。
- 请求使用 `temperature=0` 和 `stream=true`。
- 客户端必须执行超时、响应大小、重试和共享 429 冷却限制。
- 配置模型预算时，请求前必须检查明显的上下文超限。
- 输入文档必须被视为数据而不是指令。
- 除非使用受支持的跳过确认参数，正式 API 调用前必须由用户确认。

### 校验与质量

- 空响应、HTML 错误页、API JSON 和明显服务错误不得作为正常 Markdown 接受。
- 第一分片支持严格或宽松 YAML Front Matter 校验。
- 后续分片出现 Front Matter 时必须记录复核提示。
- 严重保留率或扩写率问题必须阻止保存或发布。
- 警告必须写入 metadata，并可触发复核副本。
- 质量检查至少覆盖长度、标题、题目、数字、表格、URL 和疑似广告信号。
- 质量阈值必须形成稳定策略身份；阈值变化后，已有结果必须按当前策略重新校验。

### 保存与恢复

- 分片正文和 metadata 必须成对提交；不完整写入不能被识别为完成。
- 流式中断内容可以保存为 partial 诊断文件。
- 只有缓存身份完整匹配的分片才可复用。
- 提示词身份使用 `PROMPT_IDENTITY_VERSION=2`；CRLF、LF 和单独 CR 必须规范化为 LF。
- 不同换行格式不能导致相同 prompt 被重复清洗。
- 提示词文本实际发生变化时，相关缓存必须失效。
- 旧版本生成的 LF/CRLF 提示词缓存指纹必须保持兼容。
- 缺少质量策略身份的旧分片缓存必须保持兼容；重新校验时不得仅因策略升级而重复调用 API。
- 所有预期分片有效后才能生成完整文件。
- 完整文件必须按分片编号顺序组装。
- 新候选结果校验或发布失败时，应保留旧完整文件。
- 批次支持 pending、running、succeeded、failed、skipped、interrupted 状态。
- 支持继续 pending/interrupted 文件，并为 failed 文件创建独立重试批次。

### 并发与控制

- 当前项目需求规定 `workers` 必须支持 1 到 10 的取值范围。
- 文件和分片请求必须共享有界 API 并发限制。
- 工作目录锁必须阻止多个正式实例同时运行。
- 暂停和停止文件必须位于工作目录内。
- 停止请求应停止提交新任务，并尽可能保留可恢复状态。
- 连续失败达到代码配置的阈值时自动停止。

### 输出与可观察性

- 每个源文件使用由相对路径和哈希派生的稳定输出目录。
- metadata 必须包含 schema 标识及相关哈希和配置身份。
- 日志不得输出 API Key，并应避免不必要的本机绝对路径。
- 高风险结果必须进入 `review/` 并附带复核报告。
- `review/` 副本同步失败时，文件不得记为处理成功，并且后续运行必须能够重试同步。
- 停止或处理失败时 CLI 必须返回非零退出码。

## 非功能要求

- Python 3.10 或更高版本。
- 主要用户环境为 Windows 10/11。
- 自动化检查应覆盖 Windows 和 Linux 的受支持 Python 环境。
- 密钥、源文档、输出、日志和运行状态不得进入版本控制。
- 正确性和可恢复性优先于最大吞吐量。
- 自动质量检查不能替代人工验收。

## 依赖

运行依赖：

- `httpx`
- `python-dotenv`
- `PyYAML`

开发依赖：

- `pytest`
- `ruff`
- 发布构建所需的 packaging 工具

## 最低验收

- `python -m clean_auto --help` 能正常加载。
- 所有 Python 源码和测试文件能够解析。
- 安装开发依赖后，项目测试和 Ruff 应通过。
- 发布前应完成构建和包 metadata 检查。
- 真实资料处理必须先使用测试副本，并人工检查 `output/` 和 `review/`。
- 使用真实 API 前，应确认接口兼容性、服务限制和可能产生的费用。

## 范围外

- Web UI 或 HTTP 服务。
- 数据库和数据迁移。
- 登录、认证或多用户权限。
- 向量数据库写入或 RAG 索引。
- 精确的模型 tokenizer。
- 从 SSE 字节流中间位置继续传输。
- 无需人工检查的自动最终验收。
